# Proposal

## Why

Проект пока содержит документацию и инициализированный OpenSpec. Нужен небольшой проверяемый технический каркас, чтобы доменная разработка опиралась на воспроизводимые сборки и честно разделённые проверки без доступа к пользовательскому VPS.

Это **предложение «Каркас приложения и окружение разработки»**, не описание реализованного приложения. Сейчас готовятся только артефакты для просмотра; задачи реализации остаются невыполненными.

## What Changes

- Один Maven reactor с отдельными исполняемыми backend и non-web worker и отдельный React/TypeScript frontend в том же репозитории.
- Сборочные границы и документированные точки будущего расширения научной подсистемы без научных интерфейсов и пустых доменных модулей.
- Maven Wrapper, точные стабильные версии и frontend lockfile, техническая конфигурация через окружение и безопасные примеры.
- Минимальный экран с проверкой настоящего ответа backend через стандартный технический health endpoint и явным отображением ошибки/таймаута. Запуск worker проверяет только bootstrap, без заданий и Kafka.
- Раздельные проверки сборки, запуска процессов, HTTP-связи, доступности инфраструктуры и интеграций. Linux CI проверяет реальную связь UI/backend; Windows не требует WSL2 или Docker.
- Документированный план PostgreSQL/Kafka на Ubuntu VPS. Развёртывание, обращения к серверу, реальные адреса и секреты исключены.

**За границами:** проекты и учётные записи как функции приложения, версии моделей, матрица прав, научная заглушка и контракты, задания, Kafka-сообщения, outbox, серии, перенос, CSV, графики и управление библиотеками. Выбор соответствующих технологий сохраняется, но их зависимости не добавляются ради пустого каркаса.

## Capabilities

### New Capabilities

- `development-build`: отдельные сборочные единицы, воспроизводимая установка и обычные проверки без внешней инфраструктуры.
- `technical-runtime`: проверяемый bootstrap процессов и честная техническая HTTP-связь frontend/backend без доменных API.
- `environment-verification`: безопасная конфигурация, разделение проверок, CI и план инфраструктуры.

### Modified Capabilities

Нет: действующие `openspec/specs/` пока пусты. Delta specs описывают предложенное будущее поведение и не синхронизируются в основной каталог до реализации и проверки.

## Impact

Трассировка: `REQ-ARCH-001`–`REQ-ARCH-003`, `REQ-TECH-001`, `REQ-TECH-002`, `REQ-ENV-001`–`REQ-ENV-003`, `REQ-PROC-001`, `REQ-PROC-002` из [основы проекта](../../../docs/project-foundation.md); [ADR-0001](../../../docs/adr/0001-monorepo-and-boundaries.md), [ADR-0005](../../../docs/adr/0005-selected-stack-and-async-boundary.md), предложенный [ADR-0008](../../../docs/adr/0008-proposed-tooling-and-environment.md). Предметные `SCN-*` этим каркасом ещё не выполняются; матрица связей — в [дизайне](design.md).

Точные версии, лицензии и ограничения — в [технологической основе](../../../docs/technology-baseline.md). В будущей реализации появятся сборочные файлы, минимальные процессы, тесты и CI. В текущем PR — только OpenSpec, генерируемые Codex-skills и документация. Дизайн и версии ожидают просмотра пользователем; основной стек не заменяется.
