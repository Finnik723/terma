# Spec Delta

## Purpose

Определяет технически проверяемый запуск каркаса и связь frontend/backend без подмены запуска процесса готовностью инфраструктуры или научной функциональности.

Статус: согласованные требования application-scaffold; фактическое выполнение отражено в tasks и отчёте проверки. Основания: `REQ-ARCH-001`, `REQ-ARCH-003`, `REQ-ENV-001`, `REQ-UI-004`, `REQ-UI-005` из [основы проекта](../../../../../docs/project-foundation.md), [ADR-0001](../../../../../docs/adr/0001-monorepo-and-boundaries.md), [ADR-0005](../../../../../docs/adr/0005-selected-stack-and-async-boundary.md). Технические проверки не выполняют предметные `SCN-SOLVER-001`–`SCN-SOLVER-003` и не реализуют расчётную подсистему. Прежний `SCN-STUB-001` отменён решением [ADR-0010](../../../../../docs/adr/0010-prototype-minimization-solver.md); требования REQ-BOOT и их приёмка этим не меняются.

## ADDED Requirements

### Requirement: REQ-BOOT-001 — HTTP-проверка процесса backend

Backend SHALL запускаться без PostgreSQL/Kafka и предоставлять техническую HTTP-проверку своей жизнеспособности. Её положительный ответ SHALL означать только, что процесс отвечает; он SHALL NOT подтверждать доступность инфраструктуры или расчётной подсистемы.

#### Scenario: SCN-BOOT-001 — Backend без инфраструктуры

- **WHEN** запускается собранный backend с корректной локальной конфигурацией без PostgreSQL/Kafka
- **THEN** техническая проверка возвращает положительный HTTP-ответ; документация и UI не трактуют его как готовность БД, брокера или расчётов

### Requirement: REQ-BOOT-002 — Отдельная проверка bootstrap worker

Worker SHALL иметь независимо запускаемую проверку bootstrap, завершающуюся кодом 0 после успешной инициализации и корректного закрытия контекста. Она SHALL NOT требовать PostgreSQL/Kafka, запускать научные задания или объявлять готовность потребителя сообщений.

#### Scenario: SCN-BOOT-002 — Успешная инициализация worker

- **WHEN** отдельным процессом запускается собранный worker в документированном режиме проверки bootstrap без внешней инфраструктуры
- **THEN** наблюдается признак успешной инициализации, процесс завершается кодом 0, научные задачи не выполняются, инфраструктура явно не проверена

#### Scenario: SCN-BOOT-003 — Ошибка инициализации worker

- **WHEN** проверка bootstrap не может завершить инициализацию из-за некорректной конфигурации
- **THEN** процесс завершается ненулевым кодом с понятной причиной и не выдаёт признак успешного bootstrap

### Requirement: REQ-BOOT-003 — Экран честной технической проверки

Frontend SHALL показывать обозначение технического каркаса без доступных научных расчётов. Проверка backend SHALL использовать настоящий HTTP-ответ, отдельно показывать состояния ожидания, успеха и недоступности и не объявлять PostgreSQL/Kafka или worker проверенными.

#### Scenario: SCN-BOOT-004 — Настоящая HTTP-связь

- **WHEN** пользователь запускает проверку связи и backend возвращает ожидаемый положительный технический ответ
- **THEN** frontend показывает подтверждение ответа backend, а PostgreSQL/Kafka и worker остаются в явно обозначенном состоянии «не подключены / не проверены»

#### Scenario: SCN-BOOT-005 — Ошибка или таймаут

- **WHEN** backend остановлен, отвечает ошибкой, неожиданным содержимым или не отвечает в установленный срок
- **THEN** frontend показывает недоступность или ошибку проверки и не сохраняет прежний успешный результат как актуальный

### Requirement: REQ-BOOT-004 — Ошибка запуска не маскируется сборкой

Конфликт локального порта или недопустимый технический параметр SHALL давать явную ошибку запуска соответствующего процесса. Успешная сборка SHALL NOT подменять результат проверки запуска.

#### Scenario: SCN-BOOT-006 — Занятый порт

- **WHEN** порт HTTP-процесса уже занят и запускается backend или frontend на этом порту
- **THEN** запуск сообщает об ошибке, а успешная сборка остаётся отдельным результатом; frontend не переключается молча на другой порт
