## Фактически выполненные проверки

| Проверка | Результат и смысл |
| --- | --- |
| Метасхемы | 5 схем приняты Draft202012Validator; все URN `$ref` разрешены из локального registry |
| Положительные фикстуры | 11 JSON-примеров проходят свои схемы, включая requirements со scope, свойства species и capabilities 1.0 со списком расчётных версий 1.0/1.1 |
| Отрицательная фикстура | request-invalid-input.json ожидаемо отклонён из-за отрицательного количества H; соответствующий ошибочный result проходит схему без solution |
| Регрессии | 27 unittest-тестов с положительными/отрицательными подслучаями проходят локально: исходные проверки JSON/балансов и новые случаи P1/P2; сценарий и все фикстуры находятся в Git |
| Область свойств | SYSTEM/PHASE независимы, SPECIES проверяется для всех вхождений во всех фазах; удаление свойства у второго вхождения одного speciesId отвергается, отсутствие целевых объектов не считается успехом |
| Версии | Документ capabilities 1.0 принимает 1.0/1.1; проверены точное пересечение, выбор 1.10 против 1.9, пустое пересечение, неверные идентификаторы и независимость версии документа |
| Дескрипторы | Неверные единицы/отсчёт/области стандартных свойств, дубликаты code/scope и имён опций, неверные типы, обратные/пустые диапазоны и default вне границ отвергаются схемой или семантической проверкой |
| Чистая фаза | H2O: 1 mol вещества → H=2, O=1 mol атомов; вход, итог и фаза согласованы |
| Многокомпонентная структура | Первая фаза H=1.5/O=0.75, вторая H=0.5/O=0.25 mol атомов; сумма H=2/O=1 совпадает с запросом, итогом и стехиометрией species; разные phaseInstanceId, одинаковый GAS допустимы |
| Ссылки и нейтральность фикстур | Проверены уникальность/принадлежность IDs, составы веществ, применённые модели и нулевой суммарный заряд по синтетическим определениям |
| Баланс | Для трёх успешных примеров, включая пример свойств, максимальная абсолютная невязка 0 mol атомов; сопоставлены три группы проверок и эффективные допуски |
| Перенос доли | Для каждой фазы арифметически проверено отправленное 0.25 + оставшееся 0.75 = исходному количеству каждого элемента |
| Граница capabilities | Pure-phase пример не объявляет модель смеси и свойства; структурная допустимость многокомпонентного результата не выдана за поддержку данным ядром |
| Ограничение JSON Schema | Намеренно испорченный общий баланс проходит структурную схему и отклоняется отдельной проверкой баланса; схема не доказывает семантику или минимум |
| Ненулевой exit code | Тест копирует проверяющий сценарий и фикстуры во временный каталог: сначала отдельный процесс проходит, затем после порчи temperatureK возвращает ненулевой код с причиной |
| OpenSpec | `openspec.cmd validate equilibrium-engine-contract --strict --no-interactive` и `openspec.cmd validate application-scaffold --strict --no-interactive` прошли |

Инструменты: Python **3.12.14**, готовый [jsonschema 4.26.0](https://pypi.org/project/jsonschema/) (MIT, Draft 2020-12), стандартный unittest. Все зависимости валидатора закреплены в [requirements-contracts.txt](../tools/requirements-contracts.txt), отдельно от Maven/npm приложения. [check_solver_contract.py](../tools/check_solver_contract.py) определяет корень относительно собственного файла, использует строгий JSON, локальный registry, Decimal и проверяет все Markdown-ссылки, включая contracts. В момент проверки сеть и научное ядро не нужны. Проверки из нового venv прошли; секреты и VPS не использовались.

## Воспроизведение на локальном Windows

Это фактически выполненные команды создания изолированного окружения в игнорируемом target; полный путь Python соответствует известному штатному runtime этого компьютера:

```powershell
Set-Location 'C:\Users\79067\source\repos\terma'
& 'C:\Users\79067\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m venv target/contract-validation
& 'C:\Users\79067\source\repos\terma\target\contract-validation\Scripts\python.exe' -m pip install --disable-pip-version-check -r tools/requirements-contracts.txt
& 'C:\Users\79067\source\repos\terma\target\contract-validation\Scripts\python.exe' tools/check_solver_contract.py
```

Повторная проверка — последняя команда; установки нужны только для подготовки окружения. Сценарий завершается ненулевым кодом при ошибке и не подменяет её skip.

[Официальный setup-python v7.1.0](https://github.com/actions/setup-python/releases/tag/v7.1.0) закреплён на проверенный SHA `6d4fd22b20465ccc0f7354476588e8df7c9ca0e0`, Python — 3.12.14. Обязательные ошибки шага делают job неуспешным; continue-on-error нет.

Фактический результат CI нового коммита будет указан после его завершения; прежний зелёный CI без нового шага не считается проверкой схем.

Локальные ссылки проверены как штатным средством проекта, так и отдельным обходом Markdown в `docs`, `openspec`, `contracts`, README и AGENTS. Проверка идентификаторов сравнивает foundation с исходным main; 17 отметок application-scaffold и его требования/приёмка сохраняются. Финальная проверка diff исключает код/зависимости приложения.

## Не проверялось и не реализовано

Не выполнялись минимизация, численная сходимость, SCN-SOLVER-001–SCN-SOLVER-003, HCh/Unitherm, разрешение реальной научной базы, адаптер/другой runtime, Java DTO, PostgreSQL/Kafka, UI, научное сравнение энергий, перенос/смешение как функция приложения. `CONVERGED` в синтетической фикстуре не является найденным минимумом.
