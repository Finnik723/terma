# Схемы контракта Terma 1.0

Семантика и правила совместимости — [docs/solver-contract.md](../../../docs/solver-contract.md), решение — [ADR-0011](../../../docs/adr/0011-equilibrium-contract-and-hch-adapter.md). Это схемы приложения, не интерфейсы HCh и не вычислительный модуль.

| Схема | Назначение |
| --- | --- |
| [common](common.schema.json) | Ссылки, количества, условия, общие опции, свойства и расширяемые типы фаз |
| [request](request.schema.json) | CLOSED-запрос с элементными количествами |
| [result](result.schema.json) | Успешный отдельный solution либо неуспех без solution |
| [capabilities](capabilities.schema.json) | Возможности конкретной реализации |
| [chemical-system](chemical-system.schema.json) | Версия выбранной системы: вещества, составы/заряды, определения фаз и модели |

Draft 2020-12. Все пять `$id` регистрируются в локальном валидаторе; URN не требуют сетевого обращения. Неизвестные поля 1.0 отвергаются. [Примеры](examples/README.md) задают ожидаемые положительные и отрицательные проверки. Schema defaults — аннотации: нормализацию requirements в `[]` выполняет будущая реализация, валидатор сам данные не меняет.

Не выражены в JSON Schema: конечность переполненных чисел при парсинге, уникальность ID по ключу, разрешение/совместимость ссылок, принадлежность веществ фазам, стехиометрический/общий баланс, нейтральность, T/P-применимость и соблюдение capabilities. Они проверяются отдельно по контракту. Не нужно считать наличие схем реализацией требований будущего вычисления.
