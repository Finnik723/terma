# Проекты

После входа Terma открывает список доступных проектов на `/`. В списке можно создать проект и открыть его по ссылке `/projects/{id}`. Карточка показывает название, автора, время создания и изменения. Прямую ссылку можно открыть после входа или перезагрузки страницы. [Задача №8](https://github.com/Finnik723/terma/issues/8)

## Хранение и доступ

Миграция `003-projects.xml` добавляет таблицы `project` и `project_member`. У проекта есть UUID, название, ссылка на учётную запись автора и два времени PostgreSQL. При создании времена совпадают. Одной транзакцией backend сохраняет проект и участие `OWNER` для UUID из сессии.

При каждом чтении backend проверяет наличие записи участия для UUID из сессии. Одинаковый ответ `404` используется для отсутствующего проекта и для проекта без доступа. Матрица действий по ролям относится к задаче №9. Управление участниками относится к задаче №10. [Матрица действий](https://github.com/Finnik723/terma/issues/9) · [Управление участниками](https://github.com/Finnik723/terma/issues/10)

## REST API

| Запрос | Успешный ответ |
| --- | --- |
| `GET /api/projects` | `200` и массив доступных проектов, начиная с последних изменённых |
| `POST /api/projects` | `201`, созданный проект и `Location: /api/projects/{id}` |
| `GET /api/projects/{id}` | `200` и проект, доступный пользователю |

Поля проекта — `id` (UUID), `name`, `createdBy` (имя учётной записи автора), `createdAt` и `updatedAt` (ISO 8601 в UTC). Запрос создания передаёт JSON-объект со строковым полем `name`. После удаления крайних пробельных символов Unicode название должно содержать от 1 до 120 кодовых точек. Управляющие символы внутри названия и непарные суррогаты отклоняются.

Без подтверждённой сессии API возвращает `401`. Для создания также требуется свежий CSRF-токен из `/api/auth/csrf`. При его отсутствии или недействительности запрос отклоняется с `403`. Невалидное название возвращает `400`. [Сессии и CSRF](authentication.md)

## Проверки

Компонентные тесты проверяют пустой список, создание, повторное чтение после потери ответа, прямую ссылку и истечение сессии. Профиль `postgresql-it` проверяет REST, изоляцию двух учётных записей, атомарность создания и переживание перезапуска backend с настоящей PostgreSQL. Playwright проверяет создание и открытие в браузере, перезагрузку и переход по той же ссылке из другой учётной записи. [Команды и среда проверок](development.md#linuxwindows-ci-и-пределы-проверок)
