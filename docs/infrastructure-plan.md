# План PostgreSQL и Kafka на Ubuntu VPS

Это документация следующего отдельного изменения, **не развёрнутая инфраструктура**. В `application-scaffold` нет DB/Kafka-клиентов, deployment-файлов, доменных сообщений и инфраструктурных интеграционных тестов. Подключение к VPS и запросы секретов не выполнялись.

## До выбора конкретной конфигурации

Закрыть `Q-ENV-001` и `Q-ENV-002` из [реестра вопросов](open-questions.md): узнать версию/архитектуру Ubuntu, CPU/RAM, доступный диск, сетевые ограничения и разрешённый способ администрирования. Не подставлять примерные серверные ресурсы, адреса, версии образов и настройки хранения в исполняемые файлы до получения сведений.

Выбрать защищённый канал Windows → Ubuntu: SSH-туннели или VPN. PostgreSQL и Kafka не открывать публично ради удобства разработки. Для Kafka отдельно проверить достижимость адресов, возвращаемых в broker metadata (`advertised.listeners`), через выбранный канал; доступ к одному bootstrap-порту сам по себе недостаточен.

## Отдельное инфраструктурное изменение

1. Согласовать конкретные стабильные PostgreSQL/Kafka и способ установки на проверенной Ubuntu. Docker Engine/Compose остаётся вариантом; Docker Desktop и WSL2 дома не обязательны.
2. Спроектировать приватные bind/firewall, маршрутизацию, аутентификацию, необходимые TLS-настройки и ограничение прав. Выбрать хранение секретов вне Git и без передачи их frontend.
3. Описать volumes/диски, резервное копирование, восстановление, обновления и наблюдаемость с учётом фактических ресурсов.
4. После разрешения выполнить установку и отдельные проверки: PostgreSQL connection/auth к настоящей БД; Kafka metadata и достижимость advertised addresses по защищённому каналу. Не выдумывать доменные топики и сообщения для демонстрации сети.
5. В предметном изменении добавить настоящие интеграции backend/worker. Testcontainers требует доступного Docker Engine в подходящей Linux/CI-среде; отсутствие Docker не означает успешные или пропущенные обязательные интеграционные тесты.

## Раздельная приёмка

| Категория | Требуемое подтверждение |
| --- | --- |
| Доступность PostgreSQL | Настоящее соединение и аутентификация к выбранной версии БД, не замена на H2 |
| Доступность Kafka | Настоящий broker metadata request и достижимые адреса, не один TCP connect и не фиктивный брокер |
| Прикладная интеграция | Поведение согласованного приложения на настоящих PostgreSQL/Kafka, отдельно от сетевой доступности |
| Резервирование | Проверенное восстановление, а не только наличие файла backup |

Каждое подтверждение имеет фактический статус и диагностику. Недоступная обязательная зависимость приводит к ошибке соответствующей проверки. Технический liveness backend каркаса не подтверждает ни один пункт этой таблицы.
