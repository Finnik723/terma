# ADR-0009. Согласованный объём application-scaffold

Статус: **Принято**.

Основание: пользователь разрешил реализацию после ревью PR №1; отдельно согласовал Temurin 25.0.4.1+1 вместо 25.0.5+8, у которого отсутствует Windows-дистрибутив. Связи: REQ-STAGE-003, [дизайн D-01–D-09](../../openspec/changes/application-scaffold/design.md), [технологическая основа](../technology-baseline.md).

## Решение

Принять дизайн application-scaffold и только необходимый ему набор технологий. Реализация имеет раздельные frontend/backend/worker, проверяемую сборку, конечный worker bootstrap, стандартный backend liveness, настоящий технический HTTP, безопасное окружение и раздельные Windows/Linux CI-проверки.

Точные версии не дублируются в этом ADR: источник — технологическая основа. Принятие не распространяется автоматически на весь ADR-0008, предложенные persistence/outbox/polling из ADR-0006 или семантику серий/переноса из ADR-0007.

## Последствия

Обычные локальные сборки/тесты не требуют WSL2, Docker или VPS. Playwright browser smoke выполняется в Linux CI; Windows 10 проверяется обычными сборками/тестами и браузерным UI-путём. Доступность инфраструктуры и её интеграции не считаются проверенными техническим liveness.

Доменная функциональность, расчётная подсистема/научные контракты, задания, PostgreSQL/Kafka-интеграции и развёртывание исключены. [ADR-0010](0010-prototype-minimization-solver.md) меняет требования будущего расчётного прототипа, сохраняя эти границы и приёмку каркаса. Реализация представляется отдельным PR, без самостоятельного merge. До её ревью OpenSpec не архивируется; при будущем архивировании проверяются внутренние и входящие ссылки.
