# Проверка документационного контракта

Объём: [equilibrium-engine-contract](../openspec/changes/equilibrium-engine-contract/proposal.md), [подробный контракт](solver-contract.md), [схемы и фикстуры](../contracts/equilibrium/v1/README.md). Решатель, HCh и научные данные не запускались. Этот отчёт не заменяет [проверку каркаса](verification.md).

Дата: 25 октября 2026 года. Исходная ветка создана от актуального `origin/main` с коммитом `2b4f2bd`; пользовательских изменений в рабочем дереве до начала не было. Application-scaffold уже находился в main и не архивировался.

## Фактически выполненные проверки

| Проверка | Результат и смысл |
| --- | --- |
| Метасхемы | 5 схем приняты Draft202012Validator; все URN `$ref` разрешены из локального registry |
| Положительные фикстуры | 8 JSON-примеров проходят свои схемы: request/result, capabilities и две химические системы |
| Отрицательная фикстура | request-invalid-input.json ожидаемо отклонён из-за отрицательного количества H; соответствующий ошибочный result проходит схему без solution |
| Дополнительные проверки | 18 положительных и 38 отрицательных случаев с учётом фикстур: пустой/нулевой состав, T/P, режим OPEN в request/capabilities 1.0, неизвестные поля/опции, версия, лимиты, solution при неуспехе, успех без полного provenance/баланса, свойства/единицы/отсчёт, NaN/Infinity/переполнение, повтор JSON-ключа |
| Чистая фаза | H2O: 1 mol вещества → H=2, O=1 mol атомов; вход, итог и фаза согласованы |
| Многокомпонентная структура | Первая фаза H=1.5/O=0.75, вторая H=0.5/O=0.25 mol атомов; сумма H=2/O=1 совпадает с запросом, итогом и стехиометрией species; разные phaseInstanceId, одинаковый GAS допустимы |
| Ссылки и нейтральность фикстур | Проверены уникальность/принадлежность IDs, составы веществ, применённые модели и нулевой суммарный заряд по синтетическим определениям |
| Баланс | Для обоих успешных примеров максимальная абсолютная невязка 0 mol атомов; сопоставлены три группы проверок и эффективные допуски |
| Перенос доли | Для каждой фазы арифметически проверено отправленное 0.25 + оставшееся 0.75 = исходному количеству каждого элемента |
| Граница capabilities | Pure-phase пример не объявляет модель смеси и свойства; структурная допустимость многокомпонентного результата не выдана за поддержку данным ядром |
| Ограничение JSON Schema | Намеренно испорченный общий баланс проходит структурную схему и отклоняется отдельной проверкой баланса; схема не доказывает семантику или минимум |
| OpenSpec | `openspec.cmd validate equilibrium-engine-contract --strict --no-interactive` и `openspec.cmd validate application-scaffold --strict --no-interactive` прошли |

Инструмент: Python 3.12 из штатного runtime и готовый [jsonschema 4.26.0](https://pypi.org/project/jsonschema/) (MIT, поддерживает Draft 2020-12). Валидатор установлен только в изолированный рабочий каталог вне репозитория; зависимости Maven/npm приложения не изменялись. Проверяющий сценарий использовал стандартное чтение JSON со строгой проверкой конечности/повторных ключей, локальный registry, Draft202012Validator, арифметику Decimal для фикстур и проверку локальных ссылок. Это обработка документов без оптимизатора/вызова ядра. Из-за ограничений песочницы импорт пакета и OpenSpec выполнялись с разрешённым доступом вне неё; секреты и VPS не использовались.

Локальные ссылки проверены как штатным средством проекта, так и отдельным обходом Markdown в `docs`, `openspec`, `contracts`, README и AGENTS. Проверка идентификаторов сравнивает foundation с исходным main; 17 отметок application-scaffold и его требования/приёмка сохраняются. Финальная проверка diff исключает код/зависимости приложения.

## Не проверялось и не реализовано

Не выполнялись минимизация, численная сходимость, SCN-SOLVER-001–SCN-SOLVER-003, HCh/Unitherm, разрешение реальной научной базы, адаптер/другой runtime, Java DTO, PostgreSQL/Kafka, UI, научное сравнение энергий, перенос/смешение как функция приложения. `CONVERGED` в синтетической фикстуре не является найденным минимумом. Научная достоверность и совместимость с исходниками HCh не доказаны. Реальные численные критерии/данные и интерфейсы HCh остаются в реестре вопросов.

Каркас не архивирован; main specs не синхронизированы; merge не выполняется. В новом tasks отмечаются только завершённые документальные работы и проверки, не будущие вычислительные требования.
