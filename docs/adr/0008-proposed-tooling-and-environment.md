# ADR-0008. Рекомендуемые инструменты и среда разработки

Статус: **Предложено**.

Основание: `PROP-TECH-001` в [основе проекта](../project-foundation.md). Статус относится к детализации инструментов и версий, а не к уже выбранным технологиям из [ADR-0005](0005-selected-stack-and-async-boundary.md).

## Контекст

Есть рабочие рекомендации, принятые за основу планирования. Точные версии необходимого каркасу поднабора закреплены в [технологической основе](../technology-baseline.md) и сборочных файлах; поднабор принят ADR-0009, совместные сборки и проверки выполнены ([отчёт](../verification.md)). Этот ADR остаётся предложением для прочих инструментов. У пользователя Windows 10, IntelliJ IDEA Community и локальный Codex; WSL2 не требуется. План инфраструктуры — PostgreSQL/Kafka на Ubuntu VPS с неизвестными версией и ресурсами; подключение и развёртывание требуют отдельного поручения.

## Предложение

- Eclipse Temurin JDK 25 LTS; Spring Boot 4.x, Spring MVC, Spring Data JPA, Spring Security; Maven Wrapper.
- Vite, Ant Design, React Router, TanStack Query, Apache ECharts; OpenAPI для HTTP-контракта.
- Docker Engine и Docker Compose для Ubuntu; JUnit, Testcontainers, Vitest, React Testing Library, Playwright; GitHub Actions.

Перечень перенесён из постановки как основа планирования. Необходимый каркасу поднабор принят и реализован; точная таблица версий и отложенные зависимости находятся в технологической основе. Всё остальное перечисленное остаётся предложением и сразу не устанавливается.

Проверенное ограничение: актуальный Playwright официально не поддерживает Windows 10. Browser smoke в Ubuntu CI, Node 24 LTS и конечный bootstrap worker согласованы для каркаса отдельно в ADR-0009. Эти уточнения не превращают все остальные рекомендации настоящего ADR в принятые решения.

## Обязательные ограничения среды

По `REQ-TECH-002` до установки проверяются совместимость и бесплатное использование; preview по умолчанию не выбираются, Hibernate и связанные зависимости согласуются через Spring Boot. Windows-команды, в том числе `mvnw.cmd`, документируются после появления реальных файлов.

По `REQ-ENV-002` инфраструктура доступна через защищённое соединение; SSH/VPN и настройки Kafka ещё выбираются. БД и Kafka не открываются публично ради удобства. По `REQ-ENV-003` обычные локальные проверки отделяются от интеграционных Linux/CI-проверок; Testcontainers требует доступного Docker Engine в среде тестов.

## До принятия

Необходимый каркасу поднабор и матрица проверок согласованы отдельно в [ADR-0009](0009-application-scaffold.md), включая уточнение Windows/Playwright и JDK; это не принятие всего настоящего ADR. `Q-SCOPE-001` закрыт: VPS исключён. `Q-ENV-001` и `Q-ENV-002` закрываются перед отдельной инфраструктурной работой и не требуются каркасу. Результаты реализации — в [отчёте](../verification.md); инфраструктура не развёрнута.
