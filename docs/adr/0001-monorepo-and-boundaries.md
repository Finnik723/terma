# ADR-0001. Один репозиторий и разделение обязанностей

Статус: **Принято**.

Основание: согласованный архитектурный контекст; `REQ-ARCH-001`, `REQ-ARCH-002`, `REQ-CALC-001` в [основе проекта](../project-foundation.md).

## Контекст

Нужно развивать пользовательские сценарии и асинхронные расчёты без преждевременного дробления продукта на множество микросервисов. Возможное будущее ядро и его формат пока неизвестны.

## Решение

Один репозиторий объединяет frontend, модульный прикладной backend и отдельный процесс worker. Логически разделяются оркестрация, адаптер решателя и доступ к научным данным. Оркестратор управляет сериями и переносом, решатель выполняет задачу одного реактора. Пользовательская модель, зафиксированное задание и внутреннее представление ядра — разные представления.

## Последствия

Серии и зависимости не становятся обязанностью решателя; замена ядра не должна требовать привязки пользовательских постановок к его внутреннему формату. Отдельный процесс worker позволяет отделить длительное выполнение от HTTP. Набор сборочных модулей, интерфейсы и схема данных определяются в следующих изменениях.

## Не решено

Граница полного снимка (`PROP-VER-002`) и внутренний доступ к данным HCh остаются в `Q-DOM-001`, `Q-SCI-002` в [реестре](../open-questions.md). Контракт приложения теперь закреплён отдельно в [ADR-0011](0011-equilibrium-contract-and-hch-adapter.md) и [solver-contract.md](../solver-contract.md); это не API HCh. Сборочные границы технического каркаса уже реализованы по ADR-0009, предметные границы — в [архитектуре](../architecture.md).
