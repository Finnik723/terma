# Архитектурные решения

«Принято» означает согласованное решение из исходной постановки; «Предложено» — вариант для дальнейшего технического дизайна, не обязательное требование. Ни один статус не означает, что решение уже реализовано или проверено работающим приложением.

| ADR | Статус | Тема |
| --- | --- | --- |
| [0001](0001-monorepo-and-boundaries.md) | Принято | Один репозиторий и разделение обязанностей |
| [0002](0002-demonstration-solver.md) | Принято | Явная демонстрационная заглушка вместо настоящего решателя |
| [0003](0003-model-versioning-and-conflicts.md) | Принято | Неизменяемые версии, одна текущая и атомарная защита сохранения |
| [0004](0004-libraries-and-reproducibility.md) | Принято | Версии библиотек, воспроизводимость и заменяемая расчётная подсистема |
| [0005](0005-selected-stack-and-async-boundary.md) | Принято | Выбранный стек, REST и Kafka, сохранённые асинхронные задания |
| [0006](0006-proposed-persistence-and-delivery.md) | Предложено | Хранение, polling и надёжность доставки |

| [0008](0008-proposed-tooling-and-environment.md) | Предложено | Рекомендуемые инструменты и детализация среды разработки |

Основания и постоянные идентификаторы — в [основе проекта](../project-foundation.md). Открытые детали — в [реестре вопросов](../open-questions.md). При принятии предложения нужно отразить решение пользователя и одновременно обновить связанные спецификации, обзорные документы и статус ADR; перенос контекста сам по себе такого решения не создаёт.
