# Система термодинамического моделирования

Web-приложение для геохимического термодинамического моделирования. Долгосрочная цель — рассчитывать равновесное состояние системы минимизацией энергии Гиббса с поддержкой разных фаз и дальнейшим развитием научной подсистемы. Продукт не ограничен отдельным сценарием вроде осаждения карбонатов.

Репозиторий: [Finnik723/terma](https://github.com/Finnik723/terma). HTTPS-адрес: `https://github.com/Finnik723/terma.git`; SSH-адрес: `git@github.com:Finnik723/terma.git`.

## Текущий статус

Реализован технический `application-scaffold`: отдельные backend и worker, React/TypeScript frontend, Maven Wrapper, lockfile, тесты и CI. Локальные сборки и проверки выполнены на Windows 10 без WSL2/Docker. Точные результаты и состояние CI — в [отчёте проверки](docs/verification.md).

Реализация каркаса объединена в main через PR №2. Каркас проверяет только сборку, bootstrap процессов и технический HTTP; доменная/научная функциональность и интеграции PostgreSQL/Kafka отсутствуют. Развёртывание VPS исключено. Архивирование application-scaffold — отдельное действие, не выполняемое в текущем задании.

Прототип требует временного решателя с реальным упрощённым вычислением; возврат входа отменён ([ADR-0010](docs/adr/0010-prototype-minimization-solver.md)). Документационный [контракт приложения v1](docs/solver-contract.md) и [граница адаптера будущей подсистемы HCh](docs/adr/0011-equilibrium-contract-and-hch-adapter.md) объединены в main через PR №4: CLOSED-вход в элементах, отдельный фазовый результат, capabilities, provenance и правила версий. Решатель не реализован. Совместимость с неизвестным API HCh и научная достоверность результатов не считаются доказанными; LP/H/S/V/Hipparchus остаются кандидатом реализации.

Для [задачи №6](https://github.com/Finnik723/terma/issues/6) подготовлен [план PostgreSQL/Liquibase](openspec/changes/postgresql-liquibase-foundation/proposal.md): подключение backend/worker, единые миграции и обязательная проверка настоящей PostgreSQL в Linux CI. Сейчас это только артефакты для просмотра; код, зависимости и CI не менялись. Предметное сохранение проектов, моделей, прав и расчётов потребует следующих story.

## Работа с Git и ревью

Основная ветка — `main`. Начать ревью следует с [основы проекта](docs/project-foundation.md), затем проверить архитектуру, ADR, открытые вопросы и процесс разработки. Инструкции для локального и облачного агента находятся в [AGENTS.md](AGENTS.md).

Все дальнейшие изменения готовятся в отдельной ветке и представляются через PR в `main`.

- `.gitignore` исключает локальные секреты, файлы IDE, зависимости, результаты сборок и проверок. Перед добавлением новых файлов всё равно нужно проверять их содержимое. Примеры `.env.example`, если понадобятся позже, должны содержать только безопасные значения без секретов.
- `.gitattributes` задаёт LF для текстовых файлов, CRLF для Windows-файлов `.cmd`/`.bat` и исключает преобразование бинарных файлов.
- `.editorconfig` согласует UTF-8, окончания строк и завершающую новую строку между редакторами.

Git-подготовка не добавляет лицензии на приложение или научные материалы: условия их распространения отдельно не согласованы. Учётные данные и локальная настройка авторизации в репозиторий не включаются.
