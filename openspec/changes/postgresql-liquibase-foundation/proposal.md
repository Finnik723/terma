# Proposal

## Why

В [задаче №6](https://github.com/Finnik723/terma/issues/6) требуется основа постоянного хранения: сейчас backend и worker не подключаются к БД, а их успешный запуск ничего не говорит о сохранности данных. PostgreSQL и Liquibase уже выбраны в REQ-TECH-001 и [ADR-0005](../../../docs/adr/0005-selected-stack-and-async-boundary.md); это изменение подготавливает подключение и миграции до будущих предметных story.

## What Changes

**Наблюдаемое состояние:** application-scaffold реализован; документационный контракт v1 объединён через PR №4. PostgreSQL JDBC, Liquibase, datasource и интеграционные проверки БД отсутствуют. Основной каталог спецификаций пока пуст; завершённые изменения не архивируются этим поручением.

**Предлагаемый объём реализации после просмотра плана:**

- Подключить оба JVM-приложения к PostgreSQL через внешнюю конфигурацию без адресов и credentials разработчика в репозитории.
- Ввести единый версионируемый changelog Liquibase и общий ресурсный Maven-модуль; обеспечить чистый старт, повторный и конкурентный запуск без повторного применения changeset.
- **BREAKING:** штатный запуск backend/worker потребует доступную настроенную PostgreSQL. Отсутствие конфигурации, недоступность БД и ошибка миграции будут завершать старт ошибкой.
- Добавить обязательную PostgreSQL-проверку в Linux CI, сохранив Windows-сборку и изолированные тесты без Docker/WSL2; адаптировать process/HTTP/E2E-проверки к новой зависимости.
- Обновить README, инструкции запуска и отчёт фактических проверок. Сохранность предметных объектов проверяется в будущих story, здесь — миграции и техническая запись теста.

**Граница настоящего PR:** только этот план, требования/сценарии и навигация. Установка зависимостей, код, changelog и CI пока не меняются. Действующий REQ-STAGE-005 не отменён; переход к реализации требует нового поручения после просмотра по REQ-PROC-001.

**Исключено:** предметные таблицы/CRUD/JPA-сущности, Java DTO, права и аутентификация, JSONB-снимки, Kafka/outbox/polling, решатель/адаптер и UI, установка PostgreSQL на компьютере пользователя, VPS/секреты/развёртывание, merge и sync/archive существующих изменений. ADR-0006 и открытые предметные вопросы не принимаются автоматически.

## Capabilities

### New Capabilities

- `postgresql-storage`: внешняя конфигурация PostgreSQL для backend/worker, согласованные миграции, явный отказ старта и воспроизводимая техническая проверка хранения.

### Modified Capabilities

Нет опубликованных main specs для изменения (`openspec list --specs` — пусто). Исторические delta specs application-scaffold не переписываются: новый штатный запуск с БД явно заменяет прежнее ожидание запуска без сервисов в затронутых проверках.

## Impact

Будущая реализация затронет корневой Maven reactor, `backend`, `worker`, новый модуль ресурсов миграций, их тесты/configuration, `tools/process-smoke.mjs`, окружение запуска backend в HTTP/E2E, `.github/workflows/ci.yml`, README и docs. Версии базового toolchain остаются из [technology-baseline.md](../../../docs/technology-baseline.md); новые зависимости и образ PostgreSQL предстоит проверить и закрепить при реализации.

Исходные требования и границы — [основа проекта](../../../docs/project-foundation.md), REQ-STORE-001–006; предлагаемое поведение — [delta spec](specs/postgresql-storage/spec.md), технический выбор — [design](design.md), последовательность и проверки — [tasks](tasks.md). Это готовность к ревью, не реализованное хранение и не выполнение полной user story о проектах/моделях/расчётах.
