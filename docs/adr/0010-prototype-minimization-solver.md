# ADR-0010. Упрощённый решатель с реальной минимизацией

Статус: **Принято** 25 октября 2026 года в части необходимости расчёта и разделения входа/выхода. Конкретная математическая модель и численный метод ещё не выбраны; кандидат LP/постоянных H/S/V/Hipparchus сохранён как PROP-SOLVER-001. Контракт приложения уточнён последующим [ADR-0011](0011-equilibrium-contract-and-hch-adapter.md), без реализации ядра.

Заменяет [ADR-0002](0002-demonstration-solver.md). Основание: решение пользователя после обсуждения с научным экспертом; `REQ-GOAL-003`, `REQ-SCI-003`, `REQ-SCI-008`–`REQ-SCI-012`, `REQ-STAGE-004` в [основе проекта](../project-foundation.md).

## Контекст

Возврат входного состояния без изменений позволяет проверить доставку задания, но не проверяет расчётное преобразование: входные и выходные данные решателя имеют разные назначение и состав. По решению пользователя этого недостаточно для прототипа. Доступность HCh/Unitherm по-прежнему не подтверждена и не должна становиться условием такого прототипа.

## Решение

Прототип должен использовать упрощённый решатель, действительно выполняющий хотя бы примитивную минимизацию в согласованной термодинамической постановке для одной задачи реактора. Входная постановка сохраняется отдельно от вычисленного результата и диагностики. Копирование входа, фиксированный ответ и произвольное изменение значений не заменяют минимизацию. Совпадение отдельных значений допустимо, если начальное состояние уже удовлетворяет согласованному критерию минимума и это проверено алгоритмом.

До реализации с научным экспертом согласуются целевая функция и её связь с минимизацией энергии Гиббса, переменные, ограничения, поддерживаемые вещества/фазы, условия T/P, необходимые данные и единицы. Метод, допуски, лимиты и контрольные примеры фиксируются в научной постановке и проверках соответствующей вычислительной задачи. Этот ADR не выбирает формулу, библиотеку оптимизации или термодинамическую базу.

Численное выполнение, сходимость и научная применимость различаются. Тип, версия и ограничения упрощённой модели видны в сохранённом результате, UI и CSV. Невычисленные свойства не заполняются правдоподобными числами. Ошибки входа, неподдерживаемая постановка и несходимость объясняются диагностикой и не превращаются в успешный возврат входа.

Оркестратор остаётся в worker. Серии состоят из отдельных задач реактора; перенос использует рассчитанные выходные количества поддерживаемых веществ по фазам с материальным балансом. Предложенная детализация серий/цепочек в [ADR-0007](0007-proposed-series-and-transfer.md) не становится принятой автоматически. Возможности фазовой модели предстоит определить, а не подменять заранее заданным распределением как готовым результатом.

Граница заменяемой подсистемы и версионирование данных сохраняются по [ADR-0004](0004-libraries-and-reproducibility.md). Никакой совместимости с неизвестным API HCh или форматом Unitherm не утверждается.

## Последствия и границы

Для прототипа теперь необходима вычислительная проверка согласованной упрощённой модели: нетривиальный контрольный пример, соблюдение ограничений, корректная диагностика несходимости и отдельные контракты входа/выхода. Это увеличивает объём последующей расчётной работы относительно заглушки. Научная достоверность для реальных систем и полноценное многофазное ядро остаются отдельной целью.

Объём и приёмка [application-scaffold](../development.md), согласованные в [ADR-0009](0009-application-scaffold.md), не расширяются: в каркасе по-прежнему нет расчётов, научных контрактов и заданий. Исходное поручение относилось к корректировке документов. Будущая вычислительная задача требует согласованных научных предпосылок Q-SCI-004–006, без отдельной формальной стадии согласования пакета документов.

## Проверка и открытые детали

Трассировка: `SCN-SOLVER-001`–`SCN-SOLVER-003`, `SCN-SERIES-001`, `SCN-TRANSFER-001`, `SCN-TRANSFER-002`, `SCN-UI-001`, `DEMO-005`, `DEMO-006`. Сценарии пока не реализованы и не пройдены.

Контракт Terma v1 теперь закреплён в [solver-contract.md](../solver-contract.md) по ADR-0011; его документирование не блокируется повторным выбором научной методики. `Q-SCI-004`–`Q-SCI-006` остаются для конкретной вычислительной реализации/данных/приёмки, `Q-DOM-002` — для пользовательских форм ввода, `Q-TRANSFER-001` — для оркестрации. В SCN-SOLVER-001 сравнение целевой функции использует отдельное допустимое распределение в тесте с тем же элементным балансом, а не обязательное начальное фазовое состояние в запросе. Реальное вычисление по-прежнему не выполнено.
