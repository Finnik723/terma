# Проверка аутентификации

Дата: 26 октября 2026 года. Объём и сценарии — [authentication.md](authentication.md), REST — [OpenAPI](api/auth.openapi.json).

Локально Windows 10: `mvnw.cmd verify` пройден (**10 JVM-тестов**, включая 6 backend); frontend build/typecheck и **15 компонентных тестов пройдены**, также пройдены **5 Node-проверок** конфигурации/негативного старта JAR. Компиляция PostgreSQL-профиля с `-Ppostgresql-it -DskipTests package` успешна, но это не прогон интеграции. Настоящий HTTP с тестовым account store проверяет CSRF, session fixation, старую cookie после logout, отказ неизвестным/disabled аккаунтам и cookie flags. Эта изолированная проверка не выдаётся за подключение к PostgreSQL.

PostgreSQL-профиль расширен проверкой двух аккаунтов, BCrypt hash, повторного старта без сброса пароля, disabled/SQL injection, отказа невалидному provisioning без частичных записей. Браузерный тест использует настоящий backend и PostgreSQL, проверяет вход, reload, выход, вторую запись и cookie. CI создаёт случайные временные пароли один раз на job и повторно использует их для проверки конфигурационной изоляции. Локальная PostgreSQL и браузерные проверки не выполнялись: они запускаются обязательными Linux CI jobs.

## Свидетельства CI

Реализация `35ed956` проверена в [Application checks](https://github.com/Finnik723/terma/actions/runs/40393004361). Сборки и проверки Windows Server 2022 / Ubuntu 24.04 пройдены; [process/browser job](https://github.com/Finnik723/terma/actions/runs/40393004361/job/121819662685) успешно выполнил bootstrap и оба браузерных прогона (обычный и с отличающимся environment/локальным env-файлом). Каждый прогон включает auth и исходную проверку liveness.

[PostgreSQL job](https://github.com/Finnik723/terma/actions/runs/40393004361/job/121819662655) публикует отдельный итог восьми обязательных интеграционных тестов (без skips), включая проверки учётных записей и прежние сценарии миграций/ошибок запуска. Эти результаты относятся к изолированной PostgreSQL 18.6 в Linux CI, а не к пользовательской БД или VPS. Последующие изменения этого отчёта не меняют проверенный код.

Команды обычных сборок остаются в [development.md](development.md). Проверка PostgreSQL — `./mvnw --batch-mode --no-transfer-progress -Ppostgresql-it verify` в изолированном CI-сервисе с внешними SPRING_DATASOURCE_URL/USERNAME/PASSWORD. Сессии не переживают restart, матрица проектных прав и научная приёмка в объём проверки не входят.

## Поправки по ревью, 31 октября 2026 года

Login описан как публичная операция с обязательными cookie анонимной HTTP-сессии и CSRF-заголовком, без требования предварительно аутентифицированного пользователя. То же разграничение применено к допускающему анонимную сессию logout. `GET session` сохраняет требование аутентификации; поведение backend и CSRF не менялись. `security: []` снимает наследуемую аутентификацию по [Operation Object OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html#operation-object), не отменяя обязательные параметры операции.

Frontend хранит личность отдельно от операции. Локальные typecheck/build и **21 компонентный тест пройдены**, в том числе шесть новых сценариев потери POST-ответа/ошибки GET после 204 для login/logout. Они проверяют восстановление реальной личности (включая случай, когда сервер не успел применить POST), снятие ошибки и успешную следующую операцию; автоматической повторной отправки credentials нет. Браузерный сценарий дополнен потерей ответа чтения session после настоящего login и потерей ответа уже выполненного logout, с последующим восстановлением через GET. Актуальный результат полного CI для поправок публикуется в [проверках PR №37](https://github.com/Finnik723/terma/pull/37/checks).

Provisioning-инструкция теперь использует JAVA_HOME и пути от корня репозитория. `REQ-ENV-004` делает проверенный login limiter обязательным до сетевого развёртывания; лимитер этим PR не добавлен. `REQ-ACCESS-002` фиксирует отзыв сессий для будущего управления пользователями; текущее поведение disabled не менялось.
