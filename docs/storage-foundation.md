# Основа хранения PostgreSQL/Liquibase

Статус: **не реализовано**. Источник объёма — [задача №6](https://github.com/Finnik723/terma/issues/6), REQ-STORE-001–006 в [основе проекта](project-foundation.md). Это рабочие заметки и критерии проверки, а не отдельный этап согласования перед кодом.

Подключение backend/worker и миграции не включают предметные таблицы проектов, моделей, прав и расчётов. ADR-0006, JSONB, outbox и жизненный цикл заданий сохраняют прежние статусы.

Технический вариант: единый ресурсный Maven-модуль миграций для обоих JVM-процессов; Liquibase применяет один changelog до успешного старта, с конечными ожиданиями подключения и блокировки. Datasource поступает из внешних SPRING_DATASOURCE_URL/USERNAME/PASSWORD; пароль не передаётся в CLI или URL. Новые версии JDBC/Liquibase сверяются с закреплённым BOM и лицензиями до установки. Обычные Windows-тесты изолированы от БД; обязательная интеграция работает с настоящей PostgreSQL в Linux CI. Process/HTTP/E2E получают настройки БД только в JVM, не в браузерный bundle. Техническая probe-запись теста проверяет сохранность между стартами, но не подменяет предметное сохранение через API.

Следующие сценарии — предложенная техническая детализация критериев задачи; таймауты и устройство harness можно уточнять при реализации с сохранением явного отказа, воспроизводимости и Windows-пути без Docker/WSL2.

## SCN-STORE-001 — Оба приложения используют заданную БД
- **Когда** каждое приложение запускается с внешними настройками доступной тестовой PostgreSQL
- **Ожидается** подключение и миграции используют указанную БД; JDBC-запрос подтверждает PostgreSQL, а не встроенную замену
- **И** смена тестовой БД через конфигурацию не требует пересборки JAR


## SCN-STORE-002 — Неполная конфигурация
- **Когда** у любого приложения отсутствует обязательная настройка URL, пользователя или пароля
- **Ожидается** старт завершается с ненулевым кодом в ограниченное время, без обращения к неявному localhost или встроенной БД
- **И** диагностика называет ошибку конфигурации, не раскрывая заданный пароль


## SCN-STORE-003 — Чистая БД и последовательный повторный старт
- **Когда** backend запускается на чистой PostgreSQL, затем останавливается, запускается worker и повторно запускается backend
- **Ожидается** базовый changeset отмечен выполненным ровно один раз с неизменным checksum, история и служебные таблицы Liquibase доступны обоим приложениям
- **И** тестовая техническая запись сохраняется между стартами; таблицы проектов, моделей, прав и расчётов не создаются


## SCN-STORE-004 — Конкурентный запуск
- **Когда** backend и worker одновременно запускаются с одной версией changelog на чистой тестовой БД
- **Ожидается** оба успешно заканчивают инициализацию в установленный срок, а каждый changeset записан ровно один раз
- **И** ожидание блокировки миграций ограничено; успешный старт не предшествует завершению миграций


## SCN-STORE-005 — Недоступная БД или неверный пароль
- **Когда** любой из двух процессов запускается с недоступным endpoint, неверным тестовым паролем либо теряет соединение до завершения инициализации
- **Ожидается** процесс завершается с ненулевым кодом не позднее 60 секунд, без успешного bootstrap/readiness
- **И** причина различима в журнале, пароль и credentials внутри JDBC URL не выводятся


## SCN-STORE-006 — Ошибка миграции или checksum
- **Когда** любое приложение запускается с ошибочным тестовым changeset либо несоответствием checksum ранее выполненного changeset
- **Ожидается** процесс завершается с ненулевым кодом не позднее 60 секунд без успешного bootstrap/readiness
- **И** ошибка не подавляется, история не очищается и checksum не пересчитывается автоматически ради успешного старта


## SCN-STORE-007 — Занятая блокировка миграции
- **Когда** другое соединение удерживает блокировку дольше установленного лимита
- **Ожидается** ожидающее приложение завершает старт ошибкой не позднее 120 секунд, сохраняя блокировку владельца и историю


## SCN-STORE-008 — Полный PostgreSQL-прогон
- **Когда** выполняется обязательная Linux CI-проверка хранения
- **Ожидается** она поднимает изолированную PostgreSQL, проверяет SCN-STORE-001–007 и отдельно сообщает результат интеграции
- **И** остановленные тестовые процессы и временные данные очищаются без доступа к пользовательской БД


## SCN-STORE-009 — Сервис CI не поднялся
- **Когда** PostgreSQL недоступна или проверка не может выполнить обязательный сценарий
- **Ожидается** job завершается ошибкой; успешная сборка, HTTP liveness и PostgreSQL availability не выдаются за пройденную интеграцию


## SCN-STORE-010 — Изолированная локальная проверка
- **Когда** выполняются обычные сборка и тесты на Windows без PostgreSQL
- **Ожидается** они не требуют Docker/WSL2, не поднимают встроенную БД и не пытаются подключиться к VPS
- **И** отчёт обозначает PostgreSQL-интеграцию как не выполненную локально


## SCN-STORE-011 — Process и HTTP с PostgreSQL
- **Когда** Linux CI запускает собранные JAR и существующие browser HTTP-проверки
- **Ожидается** приложения получают параметры изолированной PostgreSQL, миграции завершаются до успешного bootstrap/readiness, настоящий HTTP и изоляция frontend-конфигурации сохраняются
- **И** результат не утверждает наличие Kafka, обработки заданий или научных вычислений


## SCN-STORE-012 — Проверка инструкций и границ
- **Когда** реализация представляется на ревью
- **Ожидается** документация содержит проверенные Windows-команды и Linux CI-путь, необходимые переменные и ожидаемые ошибки без реальных секретов/адресов
- **И** фактические результаты имеют ссылки на проверки; недоступная локальная интеграция не отмечена пройденной, Kafka и предметное сохранение остаются будущей работой
