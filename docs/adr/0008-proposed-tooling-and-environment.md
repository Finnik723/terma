# ADR-0008. Рекомендуемые инструменты и среда разработки

Статус: **Предложено**.

Основание: `PROP-TECH-001` в [основе проекта](../project-foundation.md). Статус относится к детализации инструментов и версий, а не к уже выбранным технологиям из [ADR-0005](0005-selected-stack-and-async-boundary.md).

## Контекст

Есть рабочие рекомендации, принятые за основу планирования. При подготовке первого изменения точные версии, опубликованные ограничения совместимости и бесплатная доступность проверены по официальным источникам в [технологической основе](../technology-baseline.md). Совместная сборка ещё не выполнялась; этот ADR остаётся предложением. У пользователя Windows 10, IntelliJ IDEA Community и локальный Codex; WSL2 не требуется. План — frontend/backend/worker на Windows, PostgreSQL/Kafka на Ubuntu VPS с неизвестными версией и ресурсами.

## Предложение

- Eclipse Temurin JDK 25 LTS; Spring Boot 4.x, Spring MVC, Spring Data JPA, Spring Security; Maven Wrapper.
- Vite, Ant Design, React Router, TanStack Query, Apache ECharts; OpenAPI для HTTP-контракта.
- Docker Engine и Docker Compose для Ubuntu; JUnit, Testcontainers, Vitest, React Testing Library, Playwright; GitHub Actions.

Перечень перенесён из постановки как основа планирования. Для первого изменения предложен только необходимый поднабор; точная таблица версий и отложенные зависимости находятся в технологической основе. Всё перечисленное сразу не устанавливается.

Проверенное ограничение: актуальный Playwright официально не поддерживает Windows 10. Предлагается browser smoke в Ubuntu CI без обязательных WSL2/Docker дома. Существующий Node 22.14 достаточен для OpenSpec, но не для предложенного jsdom; приложению предложен Node 24 LTS. Эти уточнения и конечный bootstrap worker описаны в [дизайне каркаса](../../openspec/changes/application-scaffold/design.md) и ожидают просмотра; они не считаются новым принятым решением автоматически.

## Обязательные ограничения среды

По `REQ-TECH-002` до установки проверяются совместимость и бесплатное использование; preview по умолчанию не выбираются, Hibernate и связанные зависимости согласуются через Spring Boot. Windows-команды, в том числе `mvnw.cmd`, документируются после появления реальных файлов.

По `REQ-ENV-002` инфраструктура доступна через защищённое соединение; SSH/VPN и настройки Kafka ещё выбираются. БД и Kafka не открываются публично ради удобства. По `REQ-ENV-003` обычные локальные проверки отделяются от интеграционных Linux/CI-проверок; Testcontainers требует доступного Docker Engine в среде тестов.

## До принятия

Представить пользователю проверенные версии и предложенный объём тестов/CI (`Q-TOOL-002`, `Q-ENV-003`). `Q-SCOPE-001` закрыт: развёртывание на VPS исключено из первого изменения. `Q-ENV-001` и `Q-ENV-002` закрываются перед отдельной реальной инфраструктурной работой; для подготовки каркаса они не нужны. Статусы — в [реестре вопросов](../open-questions.md). Сейчас установлен только OpenSpec; приложение и инфраструктура не реализованы.
